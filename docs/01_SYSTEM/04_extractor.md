# 정보 추출기

크롤링된 원문에서 **청크 · 엔티티 · 관계**를 뽑아낸다. 추출은 학교 등록(또는
재크롤링)할 때 문서당 1회 실행되며, 결과는 그래프 빌더로 넘어간다.

> **결정**
> - 청킹: **공지 1건 = 1청크** 기본. 긴 문서만 재분할.
> - 스키마: **고정 타입 화이트리스트 + JSON 강제 출력**(오픈 스키마 금지 — 노드 타입 폭발 방지).
> - LLM: **API(Claude/GPT)**. 품질이 그래프 전체 품질을 좌우하고, 등록 시 1회라 비용 집중 지점.
>
> 이 문서가 엔티티·관계 타입의 **단일 기준(source of truth)**이다. 다른 문서(PLAN, 06, 10)는 여기를 참조한다.

## 1. 청킹

- 기본 단위는 크롤러가 준 문서(공지) 1건 = 청크 1개.
- 학사요람·규정처럼 긴 문서만 분할: **~500 토큰 / overlap ~50**, 문단 경계 우선.
- 분할 청크는 원문 `source_url`·`title`을 공유하고 `chunk_index`로 구분
  ([`06_storage.md`](06_storage.md) `documents` 참고).

## 2. 추출 스키마

LLM에 아래 화이트리스트를 주고 **JSON 구조화 출력**을 강제한다. 목록 밖 타입은 버린다.

### 2.1 원칙 — 엔티티 vs 속성 (노드 폭발 방지)

- **엔티티(노드)** = 여러 문서에서 다시 참조되거나 그래프로 순회할 가치가 있는 대상(학과, 부서, 담당자, 장학금, 시설, 규정…).
- **속성(`attributes`)** = 한 공지 안에서만 의미 있는 값(금액, 인원, 조회수, 신청방법 상세…)은 노드로 만들지 말고 해당 엔티티의 `attributes`(JSON)에 담는다.
- 판단 기준 한 줄: **"다른 공지가 이걸 다시 가리킬까?"** → 예면 엔티티, 아니면 속성.

### 2.2 엔티티 타입 (핵심 ●, 확장 ○)

**조직·주체**

| 타입 | 설명 | 예 |

| ● 학과·전공 | 학과/전공/학부 | 컴퓨터공학과, 응용AI융합학부 |
| ● 부서·기관 | 교내 행정·지원 조직 | 학생지원팀, 교무처 학사지원팀, 총무팀, 보건실, 어학원, 기숙사, 체력증진센터 |

### 2.3 관계 타입

`(출발 → 도착)` 시그니처 예시 포함. 목록 밖 관계는 버린다.

**조직 구조**

| 관계 | 의미 | 예 |
|---|---|---|
| 소속 | A가 B에 속함 | 학과→단과대학, 담당자→부서, 부서→대학 |
| 담당 | 업무를 맡음 | 공지/프로그램/장학금/채용→부서·담당자 |
| 주최 | 개최·주관 | 행사/프로그램→부서·외부기관 |
| 게시 | 작성·게시자 | 공지→부서·담당자 |

**콘텐츠 연결**

| 관계 | 의미 | 예 |
|---|---|---|
| 안내 | 공지가 무엇을 알림 | 공지→장학금/프로그램/채용/행사/학사일정/규정 |
| 포함 | 상·하위 구성 | 사업→프로그램, 프로그램→과목 |
| 분류 | 게시판 카테고리 | 공지→주제·카테고리 |
| 관련 | 느슨한 연관 | 공지↔공지, 프로그램↔행사 |

**대상·연락·위치**

| 관계 | 의미 | 예 |
|---|---|---|
| 대상 | 적용 대상 | 공지/프로그램/장학금→대상·자격 |
| 연락처 | 문의처 | 담당자·부서→연락처 |
| 위치 | 장소 | 시설·행사→시설·캠퍼스 |

**절차·혜택**

| 관계 | 의미 | 예 |
|---|---|---|
| 선행조건 | 먼저 필요한 것 | 절차→선행 절차, 신청→선행 요건 |
| 신청방법 | 신청 경로 | 프로그램/장학금/채용→절차·링크 |
| 제공 | 혜택 제공 | 장학금→혜택, 프로그램→혜택 |
| 첨부 | 파일/링크 | 공지→첨부·링크 |

> **날짜·기간·금액은 관계가 아니라 속성이다.** `마감일`·`신청기간`·`행사일시`·`금액`·`모집인원`은
> 해당 엔티티의 `attributes`에 담는다(예: `장학금.attributes = {"마감일":"2026-03-15","금액":"등록금 50%"}`).
> 여러 엔티티가 같은 날짜를 공유해 날짜 기준 조회가 필요해지면 그때 `일자` 노드로 승격한다(현재는 안 함).

### 2.4 속성에 담을 것 (노드로 만들지 말 것)

금액·지원액, 모집·선발 인원, 마감일·신청기간·행사일시, 신청방법 상세, 제출서류,
근무조건·급여·계약기간(채용), 자격요건 문장, 조회수·게시번호·작성일, 비고·기타 안내.

### 2.5 출력 예

```json
{
  "entities": [
    { "type": "공지", "name": "2026학년도 2학기 성적우수 장학금 안내" },
    { "type": "장학금", "name": "성적우수 장학금",
      "attributes": { "금액": "등록금 50%", "마감일": "2026-03-15", "선발인원": "20명" } },
    { "type": "부서·기관", "name": "학생지원팀" },
    { "type": "대상·자격", "name": "직전학기 성적 4.0 이상 재학생" }
  ],
  "relations": [
    { "source": "2026학년도 2학기 성적우수 장학금 안내", "relation": "안내", "target": "성적우수 장학금" },
    { "source": "성적우수 장학금", "relation": "담당", "target": "학생지원팀" },
    { "source": "성적우수 장학금", "relation": "대상", "target": "직전학기 성적 4.0 이상 재학생" }
  ]
}
```

정규화·중복 병합·임베딩은 추출기가 하지 않는다 → 그래프 빌더 담당.

## 3. 공개 인터페이스

```
chunk(document) -> [chunk_text, chunk_index]
extract(chunk_text) -> { entities: [...], relations: [...] }
```

- `extract`는 LLM 제공자의 `extract()`를 호출한다([`08_llm-provider.md`](08_llm-provider.md)).
- 반환된 엔티티/관계에는 아직 ID가 없다. ID 부여·저장은 빌더가 한다.
- 근거 추적: 호출자가 각 청크의 `doc_id`를 알고 있어, 산출물을 해당 문서에 귀속시킨다.

관련: [`05_graph-builder.md`](05_graph-builder.md), [`03_crawler.md`](03_crawler.md).
