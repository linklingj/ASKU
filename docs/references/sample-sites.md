## 관찰 — 크롤러 설계에 참고

- **공통 CMS 패턴**: 4곳 모두 서버 렌더링 `.do` 게시판(국내 대학 포털 솔루션 계열). 목록 → 상세(`subview`/게시글 상세)로 이동하고, 페이지네이션은 쿼리 파라미터로 넘긴다. 파서를 학교별로 완전 새로 짜기보다 **목록/상세 공통 셀렉터 + 학교별 오버라이드** 구조가 유리하다.
- **목록 공통 컬럼**: 번호 · (분류) · 제목 · 작성부서/작성자 · 등록일 · (조회수). → 추출 전에 이 메타를 그대로 [`documents`](../01_SYSTEM/06_storage.md) 필드(title·source_url·crawled_at)로 매핑 가능.
- **분류·작성부서 컬럼이 이미 있다**: 목록 단계에서 `주제·카테고리`·`부서·기관` 엔티티의 힌트를 공짜로 얻는다([`04_extractor.md`](../01_SYSTEM/04_extractor.md) §2.2).
- **규모**: 연세대만 8천 건 이상. 전량 크롤링은 비현실적 → 최근 N페이지 또는 기간 필터로 범위를 제한하는 정책 필요([`09_scheduler.md`](../01_SYSTEM/09_scheduler.md) 증분 갱신과 연계).
- **robots.txt·이용약관 준수**, 요청 속도 제한은 필수([`PLAN.md`](../00_BASICS/PLAN.md) §13).
