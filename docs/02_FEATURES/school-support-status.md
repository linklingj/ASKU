# 학교 지원 현황과 남은 작업

새 학교를 붙이는 일이 어디까지 자동이고 어디부터 사람 손이 필요한지 적는다.
학교를 추가하거나 수집이 깨졌을 때 여기부터 본다.

측정은 모두 `scripts/check_schools.py` 로 실제 사이트를 받아 확인한 값이다.
목록 1페이지 + 상세 2건 기준이며, 서비스는 더 많이 수집하므로 깊은 페이지의
어긋남은 여기서 잡히지 않는다.

```bash
PYTHONPATH=backend python3 backend/scripts/check_schools.py "이름=URL"
PYTHONPATH=backend python3 backend/scripts/check_schools.py --file schools.txt --autogen
```

## 1. 수집 규격을 정하는 순서

```text
전용 어댑터 클래스  →  저장된 규격  →  알려진 템플릿  →  (설정 시) LLM 생성  →  공용 파서
```

손으로 검증한 전용 클래스가 가장 앞이다. 자동 생성 규격이 잘못돼도 이미 검증된
학교는 영향을 받지 않는다. 어느 단계로도 정해지지 않으면 공용 파서로 수집하고,
그 결과는 수집 품질 지표에 남는다([`03_crawler.md`](../01_SYSTEM/03_crawler.md) §6-2).

LLM 생성은 기본으로 꺼져 있다(`SPEC_AUTOGEN`). 호출당 약 4만 토큰이라 무료 티어는
학교 몇 개면 한도에 걸린다.

## 2. 학교별 현황

### 수집 가능

| 학교 | 방법 | 목록 | 제목 | 날짜 | 비고 |
|---|---|---|---|---|---|
| 연세대 | 전용 클래스 | 22행 | 100% | 100% | 본문은 공용 파서 |
| 세종대 | 전용 클래스 | 16행 | 100% | 100% | 하위 게시판 9개 등록 |
| 홍익대 | 전용 클래스 | 10행 | 100% | 100% | 본문 K2Web 파서 |
| 성균관대 | 전용 클래스 | 25행 | 100% | 100% | |
| 아주대 | `k2web` 템플릿 | 20행 | 100% | 100% | 장학공지 자동 발견 |
| 이화여대 | `k2web` 템플릿 | 19행 | 100% | 100% | 장학공지 자동 발견 |
| 건국대 | `artclview` 템플릿 | 26행 | 100% | 100% | |
| 서울대 | 규격(손으로 작성) | 8행 | 100% | 100% | 하위 게시판 3개 자동 발견 |
| 국민대 | 규격(손으로 작성) | 20행 | 100% | 100% | 하위 게시판 8개 자동 발견 |

아주대·이화여대·건국대는 **코드 추가 없이** 붙었다. 템플릿 방식이 실제로 작동한
사례다.

### 손이 필요한 곳

| 학교 | 막힌 지점 | 필요한 것 |
|---|---|---|
| 경희대 | 상세 링크가 `javascript:view('322701','')` | 규격에 링크 조립 규칙 추가 |
| 고려대 | 상세 링크가 `#1`, 본문 27자 | 실제 이동 방식 확인 |
| 한양대 | HTML 442KB 중 텍스트 9KB, 표 0행 | 렌더링 수집기 |
| 중앙대 | HTML 1MB 중 텍스트 4KB, 표 0행 | 렌더링 수집기 |
| 서강대 | 공지 URL 404 | 올바른 주소 |

## 3. 남은 작업

순서는 **쉽고 확실한 것부터**다. 앞의 것을 마치면 이 표의 상태를 갱신한다.

- [x] **국민대 — 규격 작성 완료**
      목록이 표가 아니라 `div.board_list > ul > li` 였다. 규격 한 장으로 해결됐고
      하위 게시판 8개도 자동으로 발견된다. 이 과정에서 일반 결함 세 가지를 함께
      고쳤다 — `form` 을 통째로 지워 본문이 사라지던 문제, 페이지 번호가 1부터인
      게시판에서 페이지네이션이 제자리이던 문제, 본문 후보가 비어도 다음 후보로
      넘어가지 않던 문제.
- [x] **서울대 — 규격 작성 완료**
      지적 0건으로 통과한다. 날짜(`2026. 7. 31.`)를 읽지 못한 것은 파서가 구분자
      뒤 공백을 허용하지 않아서였고, 제목을 잃은 것은 글 제목이 `<header>` 안에
      있는데 잡음 제거가 먼저 지웠기 때문이다. 둘 다 일반 결함이라 파서를 고쳤다.
- [ ] **고려대 — 상세 이동 방식 확인**
      `#1` 뒤에 실제 이동 정보가 어디 있는지 본다. 자바스크립트면 경희대와 같은
      처리가 된다.
- [ ] **경희대 — 자바스크립트 링크 규칙**
      `javascript:view('322701','')` 에서 번호를 뽑아 상세 URL 을 만드는 유형을
      규격에 추가한다. 페이지네이션의 `form` 유형과 같은 방식이다.
- [ ] **서강대 — 공지 URL 찾기**
- [ ] **한양대·중앙대 — 렌더링 수집기 도입 여부 판단**
      Playwright 또는 Crawl4AI. 도커 이미지가 수백 MB 늘고 수집이 느려지므로,
      대상 학교가 몇 곳인지 세어 보고 결정한다.

## 4. 확인되지 않은 것

- **엔티티 추출 → 그래프 → 검색**: 공지 1건으로만 확인했다(아주대). 나머지는
  Gemini 무료 티어 할당량(429)에 막혔다. 학교 하나에 공지 수백 건이면 건당
  LLM 을 부르므로, 실제 서비스에는 유료 전환이 필요하다.
- **깊은 페이지**: 측정은 목록 1페이지 기준이다. 10페이지를 도는 실제 크롤에서
  페이지네이션이 어긋나는 경우는 수집 품질 지표로 확인한다.
